# Прелаз са x86-64 на ARM64

Овај одељак служи као кратак речник за прелазак са познатог `x86-64` кода на ARM64 код. Не треба га читати као потпун опис архитектуре, већ као мапу најважнијих разлика које ће се појавити у примерима.

## Најважнија разлика

`x86-64` дозвољава много различитих облика инструкција. На пример, неке аритметичке инструкције могу директно да читају вредност из меморије.

ARM64 је load/store архитектура. То значи да аритметика углавном ради над регистрима, а приступ меморији се ради посебним инструкцијама:

```asm
ldr w2, [x0]      // ucitaj int iz memorije
add w0, w1, w2    // saberi registre
str w0, [x0]      // upisi int u memoriju
```

Зато ARM64 код често има јаснији образац: прво учитавање из меморије, затим рачун у регистрима, па упис назад у меморију ако је потребно.

## Регистри и конвенција позива

| Идеја | x86-64 System V | ARM64 AAPCS64 |
| --- | --- | --- |
| 1. `int` аргумент | `edi` | `w0` |
| 2. `int` аргумент | `esi` | `w1` |
| 3. `int` аргумент | `edx` | `w2` |
| 4. `int` аргумент | `ecx` | `w3` |
| 64-битни аргументи | `rdi`, `rsi`, `rdx`, ... | `x0`, `x1`, `x2`, ... |
| повратна вредност `int` | `eax` | `w0` |
| повратна вредност 64 бита | `rax` | `x0` |
| frame pointer | `rbp` | `x29`, односно `fp` |
| stack pointer | `rsp` | `sp` |
| повратна адреса | на стеку после `call` | у `x30`, односно `lr`, после `bl` |

ARM64 регистри `x0` до `x30` су 64-битни. Њихови доњи 32-битни делови зову се `w0` до `w30`. Када радимо са типом `int`, природно користимо `w` регистре.

## Позив функције

На `x86-64` позив изгледа овако:

```asm
call puts
ret
```

Инструкција `call` ставља повратну адресу на стек. Инструкција `ret` је касније скида са стека.

На ARM64 позив изгледа овако:

```asm
bl puts
ret
```

Инструкција `bl` уписује повратну адресу у `x30`, који се често пише и као `lr` (`link register`). Зато функција која позива другу функцију мора да сачува `lr`, јер би следећи `bl` преписао стару повратну адресу.

Типичан ARM64 стек оквир зато изгледа овако:

```asm
stp x29, x30, [sp, -16]!
mov x29, sp

// telo funkcije

ldp x29, x30, [sp], 16
ret
```

`stp` уписује пар регистара у меморију, а `ldp` их чита назад. Облик `[sp, -16]!` прво помера `sp` за 16 бајтова надоле, па онда уписује регистре. Завршни `[sp], 16` прво чита регистре, па враћа `sp` назад.

## Сабирање

`x86-64` верзија функције `saberi`:

```asm
// int saberi(int a, int b)
// eax         edi   esi
saberi:
    add edi, esi
    mov eax, edi
    ret
```

ARM64 верзија:

```asm
// int saberi(int a, int b)
// w0          w0     w1
saberi:
    add w0, w0, w1
    ret
```

На ARM64 инструкција `add w0, w0, w1` значи: сабери `w0` и `w1`, па резултат упиши у `w0`. То је уједно и регистар за повратну вредност.

## Условно гранање

`x86-64` образац:

```asm
cmp edi, esi
jle else_grana
```

ARM64 образац:

```asm
cmp w0, w1
b.le else_grana
```

Идеја је иста: `cmp` поставља информације о резултату поређења, а условна грана после тога одлучује да ли се скаче.

Најчешћи ARM64 услови у овим примерима су:

| ARM64 | Значење за означене бројеве |
| --- | --- |
| `b.eq` | једнако |
| `b.ne` | није једнако |
| `b.lt` | мање |
| `b.le` | мање или једнако |
| `b.gt` | веће |
| `b.ge` | веће или једнако |

## Адресе у меморији

На `x86-64` смо за адресу ниске често користили:

```asm
lea rdi, [rip+msg]
```

На ARM64 ћемо за исти циљ користити пар инструкција:

```asm
adrp x0, msg
add x0, x0, :lo12:msg
```

`adrp` израчунава адресу странице на којој се симбол налази, а `add` додаје доњих 12 битова адресе. За сада је довољно да ово читамо као ARM64 облик рачунања адресе симбола.

## Практично правило

Када преводите познат `x86-64` пример у ARM64, крените овим редом:

1. Препишите потпис функције и одредите где су аргументи: `edi`, `esi` постају `w0`, `w1`.
2. Одредите где је повратна вредност: `eax` постаје `w0`.
3. Ако функција не позива друге функције, вероватно јој не треба стек оквир.
4. Ако функција позива другу функцију, сачувајте `x29` и `x30`.
5. За гранање прво потражите `cmp`, па онда преведите условни скок у `b.<услов>`.
